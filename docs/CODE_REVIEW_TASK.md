## 三、待查疑点（开发者未查清，请优先看）

### 疑点 A：成片第 213–220 帧出现"内容损坏"

**现象（用户肉眼发现，且已量化证实）**：

```
帧范围        亮度      饱和σ     高梯度像素占比     边缘锐度
205–212      120.2     76.2        13.57%          1.6x
★ 213–220    123.5     79.6        14.3→15.05% ✗   1.3x ✗     ← 异常区
221–228      120.7     76.5        13.62%          1.7x
```

**画面表现**：衣服蕾丝边缘、衣领交界处出现**锯齿状撕裂**。

**已知的段布局**（来自 `#40` 的 report）：
```
段 #0 [  0,  85)
段 #1 [ 68, 221)     ← 回看 17 帧
段 #2 [204, 323)     ← 回看 17 帧
段 #3 [306, 362)     ← 回看 17 帧
```
**213–220 落在段 #1 的尾部，同时落在段 #2 的回看区 `[204, 221)` 内。**

**关键矛盾**：这 8 帧的亮度（123.5）**既不是段 #1 主体的（133.0），也不是段 #2 新内容的（165.3）** ——看起来像"第三种状态"，即**混合/过渡的产物**。但开发者读代码后认为 `transition` 恒为 0（应当是"全用段 #1 的内容"），**与亮度证据矛盾**。

**请你回答**：
1. 阅读 `h3_upscale.py` 中调用上游 `_append_video_guarded_overlap` 的代码，以及上游该函数的实现，**确定每一段实际锁定（locked）与过渡（transition）了多少 token**，逐段列出数值。
2. 判断 `[204, 221)` 这 17 帧**实际取自哪一段的采样结果**。
3. 如果是混合，混合的权重是什么，能否解释"边缘锯齿撕裂"这一形态。
4. 如果与"全用段 #1"一致，那么 213–220 的异常**只能来自段 #1 的生成**，请指出检测/排除的方向。

### 疑点 B：接缝的"锚定"机制是否真的起作用

**设计意图**：段 N 回看 17 帧，采样时把"上一段在该处的 latent"作为关键帧条件注入，使段 N 的起始内容与前面连贯。

**请核对**：
- 该锚定条件是否**真的传到了采样器**（而不是只存在于代码里）；
- 回看帧数（17）在"帧 → token"换算中是否**始终一致**（注意 H3 的 token 网格是每 17 帧含 5 个 token：1 个独占帧 + 4 个共享帧）；
- `locked_overlap_tokens` 这个上游参数**期待的单位是 token 还是帧**，调用方传的是哪一个。

### 疑点 C：检测判据的阈值是否有实测依据

`plan["hardcut"]` 里的几个阈值是拍定的：`hunt_min_persistence=0.8`、`calm_min_quality=0.8`、`calm_too_quiet_below=0.05`。
**请指出**：哪些阈值在代码/文档中有实测支撑，哪些是纯估计；以及**没有任何数据支撑的阈值，在什么条件下会静默地让整个检测失效**。
