一句话：把"窗口边界放哪、这条缝怎么处理"从一个靠肉眼试错的参数，变成 latent 上的可测判据——但尚未做视觉验证，这是本报告最大的开放项。

一、体系全貌（数据流）

pass-1 latent (1, 24, T, h, w) │ ├─[可选] 相机补偿 _camera_compensate ← 逐帧整数位移对齐 │ ├─ 一阶 |d1| → 空间聚合 → d1_ratio = d1 / median(d1) ├─ 三阶 |d3| → 空间聚合 → d3_ratio = d3 / median(d3) │ ├─ 打分 score = max(d1_ratio, d3_ratio) ← 两者都要小 │ ├─[门] abstain: contrast = max(j3)/mean(j3) < 阈值 ? │ └─ 是 → 整片放弃，保持计划切点（硬切） │ └─ 逐 cut 决策（入口条件：残留 |boundary − measured| > seam_tolerance） ├─ calm_overlap : 取 score 最低的独占帧 + 锚定 overlap └─ jerk_hardcut : 取 jerk 峰值（3-token burst 和）+ 硬切

二、七个组件（逐个：定义 / 出处 / 实测）

① 一阶变化比值 本仓库

定义
d = mean_c,h,w | v[t+1] − v[t] |； d1_ratio = d[i] / median(d)（全片中位为基准）
位置
h3_upscale.py::_latent_change_profile
为何这样定
用全片中位而非局部邻域中位：实测（2026-09-20）局部打分在转镜处主动误导—— 转镜自己的肩峰会抬高邻域中位数，反而把真转镜压到低于两格外的偶然波动。 像素域复核：转镜 2.72× 中位，安静段 1.25×。

② 三阶变化比值（jerk） 思路借自 MAINodes

定义
j3 = mean_c,h,w | v[t+3] − 3v[t+2] + 3v[t+1] − v[t] |； d3_ratio = j3[i] / median(j3)，居中对齐到与 d1 同一时间格
位置
h3_upscale.py::_latent_change_profile（第二段）
出处
IDEA 借鉴 自 MAINodes 的 H3 Jerk Oracle （matlowai，GPL-3.0-or-later，与本包同许可）。未复制代码，仅按其论证重新实现。
它的论证
值域一阶被"运动能量"污染：纹理物体划过让该处值脉动， 而脉动在任何阶的差分都大——它实测 corr(|d1|,|d3|) = 0.96–0.98。 |d3| 测的是运动"变化得有多突兀"。
★ 用法相反
它的 oracle 找高 jerk（会糊、要重绘的区域）； 我们找低 jerk（该放边界的地方）。同一信号，反向使用。

③ 组合打分 本仓库

定义
score = max(d1_ratio, d3_ratio)（取较差的那个）
理由
单看一阶会选中"匀速运动"（drifter：速度高但 jerk 低）； 单看三阶会选中"平稳但突变"的点。两者都小才算平缓。
实测反例
构造 {170:(d1=0.30, d3=9.00), 204:(d1=1.20, d3=0.30)}： 旧判据选 170，新判据正确否决它、选 204。

④ 相机补偿 思路借自 MAINodes

定义
对每个 token，在 ±max_shift（默认 3）内搜索使 mean|roll(cur) − prev_aligned| 最小的整数位移 (dy,dx)， 累积应用；边缘 wrap（torch.roll）。
位置
h3_upscale.py::_camera_compensate
出处
同上（MAINodes，GPL-3.0-or-later，思路重实现）。
它的实测记录
原文："panrun 的过度膨胀（124 → 345 帧）就是平移本身被算成 jerk 造成的"
本仓库实测
合成"纯平移"（每帧整体挪 2 格，内容不变）： mean |d1| ratio 1.00 → 0.00（补偿后完全不产生变化信号）
动机
本仓库的提示词模板提供 14 种运镜。没有补偿时， Truck/Arc 会被读成剧烈运动，calm 搜索会绕开本该可用的边界。

⑤ 空间聚合 MAINodes 列了三种

定义
mean｜max｜top-decile （把 (1,C,T,h,w) 压成 (T,)）
位置
h3_upscale.py::_reduce_hw
诚实说明
测试证明：归一化之后三者无法用"峰值 ratio"区分—— 各自除以自己的 median，单个热点在三种模式下峰值都等于 1.0。 它是否在真实片（局部与全局运动混合）上带来收益，尚未验证。

⑥ 放弃门（abstain） 思路借自 MAINodes

定义
contrast = max(j3) / mean(j3)；若 contrast < calm_abstain_below → 整片不做搜索，保持计划切点。
位置
h3_upscale.py::find_calm_boundaries 开头
出处
MAINodes 的同名概念，原文： "the quantile can rank but cannot abstain"——排名管不了"这里根本不需要动"。
本仓库实测
全平坦 profile + 阈值 1.5 → 返回 [187] / overlap 0，并注明 clip too flat for a search； 阈值设 0（关闭）则正常搜索。

⑦ 两种缝策略 本仓库

策略边界选在缝的处理依据
calm_overlap（默认）score 最低的独占帧

五、已知弱点（请重点审这几条）

  • 未做视觉验证——所有判据只在 latent 与合成数据上验证过。 成片观感（接缝是否真的看不见）尚无量化结论。
  • 空间聚合三模式在归一化后无法区分（见组件⑤）， 收益未被证实，属"提供但未验证"。
  • 相机补偿只在合成纯平移上验证； 真实运镜含透视变化，整数位移对齐只是近似。
  • 只在独占帧（17k，即相位 0）上选边界， 因此未采用社区的 phase-norm / detrend-phase（同相位相比时收益为零）。
  • 历史真崩溃：F.pad(mode="replicate") 不接受 1-D 张量， 导致 |d3| 列在真实计算路径上抛 NotImplementedError。原因：早期测试直接构造 profile 喂给下游函数， 绕过了计算路径。已修复（改 torch.cat 手工 edge pad）， 并新增走真实路径的测试。这条可以质疑：是否还有其他只测中间结构的盲区。
  • 三阶差分在 token 数 < 4 时退化为全零（此时无 jerk 信息）。
