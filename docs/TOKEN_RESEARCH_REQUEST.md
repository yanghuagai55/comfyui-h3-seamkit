## 0. 一句话

我们靠**逐条手调参数**在修分块采样的接缝，已经调不动了。
我们缺的不是更多工具，而是**对 token 变化本身的模型** —— 现在所有判据（一阶差、jerk、持续性、安静度）
都是**猜出来的启发式，从没在真实数据上标定过**。

---

## 1. 背景：我们要解决什么

**目标**：在 8GB 显存的单卡笔记本上生成/放大 **MiniMax H3** 的长视频。

**硬件约束逼出来的做法**：整片按时间切成若干**窗**，逐窗采样，再拼回整片。

**由此产生的核心缺陷**：

> 每窗在**自己的条件上下文**里独立去噪，收敛点由局部动力学决定 →
> 即便起始噪声完全相同（上游已实现全局噪声按 token 坐标精确切片），
> 两条轨迹仍会收敛到**不同的局部最优** → 拼接处出现**曝光/色彩/纹理台阶**。

这个台阶是实测到的，不是推测：同一段内容、两个相邻窗，段首单帧跳变可达 **35~45 灰阶**
（基线 tag `v1.0.0-baseline-20260921`）。

## 2. 已经确定的 token 几何（这部分不是问题）

| 事实 | 值 |
|---|---|
| 时间分组的帧数 | **17 帧一组**（`FRAME_GRID = 17`） |
| 每组包含的 token | **5 个**，其中 1 个是「**独占帧**」（只覆盖 1 帧），其余 4 个各覆盖 4 帧 |
| 帧 → token | `token_of(frame) = frame // 17 * 5` |
| **窗口边界能落在哪** | **只能落在独占帧上（17 的整数倍）** ← 硬约束，实测：起点落在非独占帧会在该窗首 token 崩 |
| 整片帧数 | `17n + 5` |
| 一 token 平均覆盖 | ≈ 3.4 帧（24fps 下 ≈ 0.14 秒） |

**这条硬约束的后果**：模型真正的转镜帧落在任意帧上，而我们的缝**只能落在 17k 上** ——
所以残差（缝到转镜的距离）**天然最大是 8 帧（17/2）**，这是网格量化误差，不是选择。

## 3. 核心缺口：我们不知道 token 变化「长什么样」

诚实列一遍。**已知的少，未知的多。**

### 3.1 已经实测到的（可复用碎片）

| 结论 | 证据 |
|---|---|
| **缝正落在模型自己的转镜上时，硬切最干净** | 残差 0~2 的硬切实测无可见台阶 |
| **安静处的锚定叠化效果好** | 像素域：段间亮度差 31.06 → **14.33** 灰阶；缝窗重去噪：台阶 5.30x → **1.72x** |
| **细节密的区域重生成会被注入伪纹理** | 自由区锐度（Laplacian 方差）**+23~35%（每一帧都涨）** vs 平滑区 **+2~13%（零散）** |
| **最静的地方反而不能放缝** | 近静止段被解成「三帧相同 + 一帧轻推」的量化棘轮，静止时最显眼 |
| **同种子不可逐位复现** | 一采跨会话结果就变（同 seed 同 prompt，hunt 测得的转镜帧 200 → 209）；二采本底差 2.8~4.5 灰阶 |

### 3.2 完全不知道的（**这才是本请求书的重点**）

1. **转镜在 latent 上的签名究竟是什么？**
   我们用「一阶差 + 三阶 jerk + 持续性」三个分去猜。**没有一个是在真实转镜数据上标定过的。**
   三个分在什么内容下会互相打架？谁最可信？

2. **假阳性长什么样、怎么挡？**
   实测反例：一段**连续特写**（人物没换镜头，只有手在挥），hunt 判成转镜并**硬切**了（比 40.56 灰阶的台阶）。
   我们的「持续性门」**没挡住它**。那么：
   - 「手挥过」和「真转镜」在 latent 上到底差在哪？
   - 阈值该定在哪？现有 0.80 是拍的。

3. **什么样的内容重生成是安全的？**
   实测：细节密的自由区被注入伪纹理，平滑的没事。但——
   - 为什么？是「模型还原不出高频」还是「两侧锚本身不一致」？
   - **可测量的判据是什么？**（我们猜是「自由区细节密度」，但只有 n=2 的样本）

4. **「差 1 帧」为什么反复卡住？**
   三次实测，残差都是 **5**，而门限是 4 —— 一次是巧合吗？残差 5 与残差 2 在视觉上到底差多少？

5. **量化棘轮的适用范围**
   已知它出现在「近静止」段。那么「慢速连续运动」能不能掩盖它？临界速度是多少？

6. **为什么不可复现？**
   一采/二采都不是逐位可复现。是融合注意力（SageAttention / chunked attention）？
   是 bf16 累积？能不能通过某种设置恢复确定性？

## 4. 已有检测工具，以及它们各自的由来

**请先看这一节再动手** —— 这些工具是「踩坑记录」的沉淀，每个背后都有一个具体的失败。

### 4.1 `_latent_change_profile` —— latent 变化画像（`h3_upscale.py`）

每个 token 一行，给三个分：

| 分 | 做法 | 由来 |
|---|---|---|
| **一阶差 d1**（local / global 两版） | `|v[t+1] − v[t]|`，分别按**自身 ±2 邻域**中位、**全片中位**归一化 | 基础量 |
| **三阶差分 d3（jerk）** | 三阶差分的绝对值 | **IDEA 重新实现（未拷代码）自 MAINodes 的 H3 Jerk Oracle**。由来：MAINodes 记录过「**摇镜本身会被判成剧烈运动**」—— pan 让 over-dilation 从 124 帧涨到 345 帧。jerk 标记的是**模型开始放弃并抹开**的位置 |
| **相机补偿** | 逐 token 求 (dy,dx) 整数位移，把稳定摇镜读成静止 | 同样源自 MAINodes 的 pan 教训 |
| **`persistence`（持续性）** | 变化前的 token 均值状态 vs 变化后的均值状态之差，按 clip 自身最大值归一化 | **IDEA 源自 PERSIST（arXiv:2608.29287）**。该论文把「镜头边界」重述为：局部变化**必须伴随 latent 状态的持续更新**，而不是「震荡一下又回原趋势」；作者报告能减少闪烁/字幕/档案素材造成的 33~80% 误检。**我们只做了一个朴素的窗口均值差，不是他们的 FiLM 分类器** |

**局限**：三个分全是手工启发式，**没有在任何人工标注的转镜集上评过**。

### 4.2 `_align_to_profile` —— 找转镜帧（hunt）

- 在每个计划切点附近**全窗口取 argmax**，再把结果**吸附到最近的独占帧**（不是「只在独占帧里 argmax」）
- **教训（实测）**：只在独占帧里挑最高分是错的 —— 归一化会把转镜**自己的肩峰**抬高邻域中位数，反而把真转镜压下去，
  选到两格之外的偶然波动（实测：计划 68、真转镜 ~66，却选中 85）
- **教训**：**搜索半径与残差阈值必须是两个数**。原来共用一个，小阈值下 hunt 直接全灭

### 4.3 `find_calm_boundaries` —— 缝放哪 + 硬切还是混合

两个**方向相反**的策略（**这就是本请求书第 5 节要改的地方**）：

| 策略 | 赌什么 | 动作 |
|---|---|---|
| `calm_overlap` | 「安静处混合看不出来」 | 挪到附近**最安静**的帧 + 锚定重叠 |
| `jerk_hardcut` | 「运动掩盖接缝」 | 挪到**最剧烈**的帧 + 硬切（不混合） |

外加一堆门：安静度质量门 / 过静门 / 相对增益门 / 负载护栏。
**这些门限（0.8 / 0.05 / 0.15 / 4）全是拍的** —— 实测反复出现「差 1 帧卡住」「只安静 8% 不够 15%」。

### 4.4 像素域验证工具（旁路，不进生成链）

| 工具 | 干什么 | 为什么需要它 |
|---|---|---|
| 逐帧跳变 + 局部中位比 | 找肉眼级台阶 | 数字能定位，但**会漏** |
| **帧拼图 / 对照拼图** | **目视复核** | ★ **两次都是靠它才抓到真问题**（数字说"好了"，画面说"多了道弧线"） |
| 锐度（Laplacian 方差） | 量「有没有被注入伪纹理」 | 区分「抹平」与「加料」 |
| `analyze_cut.py` | 量成片实际在第几帧转镜 | 对照 hunt 的判定 |

### 4.5 像素域修复工具 `seamfix`（旁路）

跨段色彩对齐 / 亮度平滑 / 去抖 / 叠化，配浏览器实时调参界面。
**教训**：整条流水线每步都是**逐像素乘性变换**，所以在直方图域可精确复现，一次重映射 ~9ms。

### 4.6 缝窗重去噪（E-3，已实测有效）

- **机制**：RePaint 式逐步锚定（每步把锁区钉回已发布 latent），中段在双侧上下文里重生成 —— **零上游改动**
- **实测（干净的 A/B：同一份二采输入，只切开关）**：台阶 **5.30x → 1.72x**
- **锁区按构造不变**（每步被钉回锚）
- **但**：细节密的自由区会被注入伪纹理（见 3.1）

## 5. 我们希望的策略（**请研究来支撑它**）

原话整理如下：

> **硬切很好。** 我希望**只差那几帧的时候，直接去掉**（重叠），可以省去混合的麻烦、
> 生成快，而且可以避免「多种变化较大的画面混合后出现奇怪的崩坏或者其他结果」，
> 同时又**保留现在已经验证了的「安静时候混合」的策略**。

翻译成一张策略表：

| 情形 | 期望动作 | 依据 |
|---|---|---|
| 缝 ≈ 转镜（差几帧） | **硬切，不混合** | 省时间；且避免把两个"变化大"的画面混在一起 |
| 区域**安静** | **锚定重叠（混合）** | ★ **已验证有效**，要保留 |
| 区域**闹 / 细节密** | **？** ← **这就是要研究的** | 实测会被注入伪纹理，但不知道怎么判、怎么处置 |
| 拿不到转镜 | **？** | 现在退回"计划帧 + 重叠"，但没有依据 |

**期望的最终形态**：给定一段 latent，程序自己决定
**缝放哪 / 硬切还是混合 / 混合窗多宽** —— **零手调**。

## 6. 期望的研究产出（按价值排序）

### 第一层：**分类学** —— token 变化的可测量签名
把 token 变化分成几类，并给出**各自的可测量特征**：
- 真转镜
- 相机运动（推/摇/移）
- 局部快速物体（手挥、物体掠过）
- 纹理闪烁 / 细节抖动
- 量化棘轮

### 第二层：**判据** —— 把手调的门换成有物理意义的量
现在手调的有 6~7 个门。希望压缩成 1~2 个**有物理意义、能解释**的量，例如：
- 「自由区细节密度」→ 决定**能不能在此重生成**
- 「转镜置信度」→ 决定**能不能硬切**
并给出**标定方法**（用什么样的标注数据、怎么算指标）。

### 第三层：**自动化与可复现**
- 自动决定第 5 节那张策略表
- 找出**让采样可逐位复现**的办法（或证明不可能），因为现在的 A/B 全靠"同会话缓存"这一个技巧

## 8. 术语表

| 术语 | 含义 |
|---|---|
| **独占帧** | 每 17 帧里那个只覆盖 1 帧的 token（17 的整数倍）—— 窗口边界唯一能落的地方 |
| **残差** | 最终边界与「测得转镜帧」的帧距。因网格约束，**最大 8** |
| **锚定 overlap** | 新窗首 token 锚在上一窗已发布输出上的重叠拼接 |
| **缝窗重去噪** | 拼完之后，对缝取短窗、两端锁死为已发布 latent、中段重新生成 |
| **负载护栏** | `最长段帧数 × 二采画布MP` 不得超过实测 OOM 锚点（191） |
| **量化棘轮** | 近静止段被解成「三帧相同 + 一帧轻推」的现象 |
